# 咖啡店音效接入说明

## 1. 咖啡店不是另一套 AudioManager

整个游戏仍然只有一个全局 `AudioManager`。它在第一次播放时自动创建并跨场景保留，咖啡店、战斗、主菜单和其他场景都共用它。

不同场景只需要不同的“业务事件翻译器”：

```text
全局 AudioManager + AudioCue
├─ BattleAudioPresenter：理解战斗事件
├─ CafeAudioPresenter：理解咖啡店 GameEvent
├─ AudioInteractionFeedback：理解点击、按下、拖拽等通用交互
├─ AudioButtonFeedback：理解按钮 Hover / Click
└─ AudioCuePlayer：理解 UnityEvent、Animation Event 和对象启用
```

Presenter 不是 Manager，也不会创建第二套音量或 AudioSource。它只负责告诉同一个 Manager“现在应该播放哪一个 Cue”。

把所有场景的业务事件塞进一个巨大 Bindings 资产，会让战斗人员看到研磨机字段、咖啡店人员看到破韧字段，反而难用。因此播放底层全局共用，业务映射按领域分开，是更清晰且可扩展的结构。

## 2. 咖啡店为什么需要三种接入方式

咖啡店声音虽然多，但可以分为三类：

| 类型 | 例子 | 使用方式 |
| --- | --- | --- |
| 全局业务结果 | 顾客到店、创建订单、订单完成、金币到账、营业阶段变化 | `CafeAudioPresenter + CafeAudioBindings` |
| 局部交互 | 材料拿起、杯子拖动、菜单按下、鼠标悬浮 | `AudioInteractionFeedback` 或 `AudioButtonFeedback` |
| 精确时机 | QTE 评分、机器动画某一帧、倒水落杯瞬间 | `CafeQteAudioFeedback`、`AudioCuePlayer` 或 Animation Event |

不能只用一种方式解决全部声音。例如“鼠标开始拖动”是局部输入事件，而“订单正确完成”是业务成功事件；它们的触发语义完全不同。

## 3. 创建咖啡店集中映射表

1. 在 Project 窗口右键；
2. 选择 `Create → KiKs → Audio → Cafe Audio Bindings`；
3. 命名为 `CafeAudioBindings_Default`；
4. 选中资产；
5. 将对应 AudioCue 拖进字段。

### Day And Shop Flow

| 字段 | 对应事件 |
| --- | --- |
| `Morning Check Started` | 进入早晨选材料阶段。 |
| `Shop Started` | 正式开始营业。 |
| `Night Started` | 进入夜晚阶段。 |
| `Day Ended` | 一天结束并准备离开 Cafe 场景。 |
| `Shop Ready To Close` | 最后一位顾客离开，可以结算关店。 |

### Customer And Dialogue

| 字段 | 对应事件 |
| --- | --- |
| `Customer Arrived` | 顾客进入咖啡店。 |
| `Customer Ready To Order` | 顾客开始下单。 |
| `Dialogue Opened` | 普通对话请求出现。 |
| `Dialogue Ended` | 对话结束。 |
| `Wrong Coffee` | 提交错误咖啡。为空时回退使用 Dialogue Opened。 |

### Order And Reward

| 字段 | 对应事件 |
| --- | --- |
| `Order Created` | 订单正式创建。 |
| `Coffee Served` | 自由选择流程提交咖啡。 |
| `Order Completed` | 正确交付并完成订单。 |
| `Revenue Awarded` | 金币到账。 |
| `Perfect Order Bonus` | 全 Perfect 订单的额外声音，会与 Revenue Awarded 叠加。 |

### QTE Result

| 字段 | 对应评级 |
| --- | --- |
| `Qte Perfect` | Perfect。 |
| `Qte Good` | Good。 |
| `Qte Miss` | Miss。 |

### Additional GameEvent Channels

这是扩展列表，处理以后新增或比较特殊的咖啡店业务事件。每一项包括：

| 字段 | 作用 |
| --- | --- |
| `Display Name` | 仅供 Inspector 阅读，例如“研磨完成”。 |
| `Channel` | 必须与业务代码 `GameEvent.Emit` 使用的频道字符串完全一致。 |
| `Cue` | 收到该频道时播放的 AudioCue。 |
| `Volume Scale` | 该映射额外乘上的音量，1 表示不改变 Cue 音量。 |

注册人员不需要修改 Manager。新增咖啡业务事件时，由负责该功能的程序员发出一个明确 GameEvent，并把频道名告诉音效注册人员；注册人员只需在 Additional Events 增加一项。

## 4. 在 Cafe 场景安装 Presenter

1. 打开 `Assets/Scenes/Cafe.unity`；
2. 新建空对象，命名为 `CafeAudio`；
3. 添加 `Cafe Audio Presenter`；
4. 把 `CafeAudioBindings_Default` 拖入 `Bindings`；
5. 保存场景。

Presenter 字段：

| 字段 | 作用 |
| --- | --- |
| `Bindings` | 本咖啡店场景使用的集中音效表，必须填写。 |
| `Log Received Events` | 注册调试时开启，会在 Console 输出收到的频道。正式版本建议关闭。 |

一个 Cafe 场景通常只放一个 CafeAudioPresenter。放两个会导致同一个事件播放两次。

## 5. 材料、杯子、水壶等杂项交互

对材料图标、杯子、水壶、菜单等对象添加 `Audio Interaction Feedback`。它不修改原有拖拽脚本，可以与 `MaterialIcon`、`CupContainer`、`Kettle` 等组件并存。

### Pointer

| 字段 | 触发时机 |
| --- | --- |
| `Pointer Enter` | 鼠标进入对象。 |
| `Pointer Exit` | 鼠标离开对象。 |
| `Pointer Down` | 鼠标/指针按下。 |
| `Pointer Up` | 鼠标/指针松开。 |
| `Pointer Click` | 完成点击。 |

### Drag And Drop

| 字段 | 触发时机 |
| --- | --- |
| `Drag Started` | 开始拖动。适合材料拿起、杯子拿起。 |
| `Drag Released` | 松开拖拽物。注意：这只代表松手，不代表业务上放置成功。 |
| `Received Drop` | 有对象被拖放到当前对象上。 |

如果声音必须只在“材料确实成功进入机器”时播放，不要使用 Drag Released。应让业务成功点发出 `MaterialPlaced` 等 GameEvent，再通过 Additional Events 映射，以免无效拖放也有成功音效。

## 6. QTE 音效

在五种 QTE Prefab 根对象上：

1. 添加 `Cafe QTE Audio Feedback`；
2. 把同一份 `CafeAudioBindings_Default` 拖入 `Bindings`；
3. 保存 Prefab。

组件会监听该 Prefab 上的 `QTEBase.OnQTEDone`，根据 Perfect、Good、Miss 自动选择集中映射表里的 Cue。

## 7. 动画和机器精确帧

研磨、倒水、蒸汽、压制等声音如果必须与动画帧同步：

1. 在动画对象上添加 `Audio Cue Player`；
2. 把 Cue 拖入 `Cue`；
3. 在 Animation Event 中调用 `Play()`。

持续工作声不建议伪装成大量重复短音效。当前 Manager 面向短音效；真正需要循环的研磨机、蒸汽或环境声，后续应增加专门的循环声音句柄，或者由机器自身的循环 AudioSource 管理开始与停止。

## 8. 咖啡店扩展规则

新增声音时先判断：

1. 是全局业务结果吗？使用 GameEvent + CafeAudioBindings。
2. 是普通鼠标/拖拽反馈吗？使用 AudioInteractionFeedback。
3. 是按钮吗？使用 AudioButtonFeedback。
4. 是动画精确帧吗？使用 AudioCuePlayer。
5. 是 QTE 评级吗？使用 CafeQteAudioFeedback。
6. 是持续循环机器声吗？不要用反复 TryPlay 模拟，应使用循环声音方案。

这样咖啡店即使以后增加几十种机器和材料，AudioManager 仍然不需要增加任何咖啡店字段；变化只发生在 Cue、Bindings 和业务事件适配层。
