# E1 发布前代码审查报告

- 审查日期：2026-08-11
- 审查范围：`Assets/Script` 全部 190 个业务脚本 + `Assets/Shaders/CardFire` 2 个运行时脚本 + 构建场景列表 + StreamingAssets 卡牌数据
- 审查方式：5 组并行深度代码审查（按系统拆分）+ 关键结论人工复核
- 目标平台：Windows Standalone（当前 `scriptingBackend` 默认 Mono，`activeInputHandler=1` 新输入系统）

---

## 一、结论摘要

**代码整体工程质量良好**：事件订阅普遍成对退订（未发现伤害/奖励翻倍类重复订阅）、DOTween 清理纪律好、跨场景单例与静态状态重置基本规范、StreamingAssets 路径拼接正确、无编辑器 API 混入运行时。

但发布前存在 **6 个必须修复（P0）** 与 **12 个强烈建议修复（P1）** 的问题，其中 4 个是"发布版玩家可触发"的调试残留/经济漏洞，必须处理。

## 二、P0 — 发布阻断，必须修复

### P0-1 调试快捷键残留，发布版玩家可触发作弊（3 处）
| 位置 | 内容 |
|---|---|
| `CoffeeShop/CafeFlow/TimeSystem.cs:43-52` | **F9 直接跳过整个经营日**，无任何条件编译保护 |
| `CoffeeShop/Dialogue/DialoguePlayer.cs:49-58` | F8 跳过对话 |
| `Combat/Event/EventSceneController.cs:166-172` | F8 跳过事件对话 |

修复：三处均包进 `#if UNITY_EDITOR || UNITY_DEVELOPMENT_BUILD`，或直接删除。

### P0-2 收集按钮可无限刷材料（经济漏洞）
`CoffeeShop/Unlock/CollectController.cs:33-40`
`OnCollect` 无冷却、无次数上限、不禁用按钮，`collected1/2` 仅计数。玩家可无限点击无限领取 `rewardResourceId`（默认 CocoaPowder），直接破坏游戏经济。
修复：领取后 `collectButtonX.interactable = false`；或用 `RuntimeGameRepository` 一次性标记防重领。

### P0-3 事件场景 end 卡：金币不足不扣钱却照发奖励
`Combat/Event/EventSceneController.cs:660-692`（对照 `776-798`）
- `ResolveCard` 的 `"end"` 分支：`ApplyCosts()`（void）内 `SpendGold` 失败只 `return` 退出函数，**调用方继续无条件执行 `ApplyRewards()`** → 玩家金币不足时白拿全部奖励。
- `"effect"` 卡分支（788-795）正确写了 `FinishEvent(); yield break;` 保护，两路径行为不一致。
修复：`ApplyCosts` 改为返回 bool，`ResolveCard` 的 end 分支失败时 `FinishEvent(); yield break;`，与 effect 卡对齐。

### P0-4 事件卡牌奖励双发（配置两个字段时翻倍）
`Combat/Event/EventSceneController.cs:723-743` 与 `826-848`
`cardRewardMode`（随机一张）与 `cardRewardIds`（全部指定）是**顺序执行的两个独立 if**，注释（`EventDefinitions.cs:53`）声明"cardRewardIds 优先于 cardRewardMode"，实际同时配置时"随机卡 + 全部指定卡"都会发放。`ResolveAttackCard`（884-903）用的 `else if` 才是正确的。
修复：改为 `if (cardRewardIds 非空) { 逐张给 } else if (cardRewardMode 非空) { 随机给 }`。
> 注：已检查当前事件 JSON 数据是否同时配置两字段——需人工确认（数据在 `StreamingAssets/Event/`）。

### P0-5 战斗卡肉（hitstop）可致全局时间永久冻结
`Combat/Runtime/VFX/PlayerAttackFeedback.cs:398-404`（近战）与 `441-445`（远程）
```csharp
Time.timeScale = 0f;
...
yield return new WaitForSecondsRealtime(hitstopDuration);
Time.timeScale = 1f;
```
若协程在挂起期间被中断（`SetActive(false)`、场景卸载、`StopCurrentAttack` 之外的打断路径），`timeScale` 永久停在 0 —— **整个游戏冻结且无任何日志**。组件没有 `OnDisable` 兜底。
修复：加 `OnDisable`/`OnDestroy` 强制 `Time.timeScale = 1f`；或改用 `try/finally` 恢复；`StopCurrentAttack` 已恢复但覆盖面不足。

### P0-6 作弊面板：Development Build 自动启用
`Debug/LoopDebugCheats.cs:1,43-50`
整个类被 `#if UNITY_EDITOR || DEVELOPMENT_BUILD` 包裹，`[RuntimeInitializeOnLoadMethod]` 自安装 + `DontDestroyOnLoad`，F1-F12 全部作弊（+500 金币、全解锁、跳天、直接结算）常驻 OnGUI 面板。
**Release 构建不编译，安全**；但勾选 Development Build 的任何构建都会带上且无开关。
修复：发布流程硬性检查——**最终包必须是不勾选 Development Build 的 Release 构建**；或把条件改为仅 `UNITY_EDITOR`。

## 三、P1 — 强烈建议修复（发布风险）

### P1-1 转场失败无兜底，场景跳转静默失效
- `UI/TransitionExitPanel.cs:84`：`mat == null` 时 `Debug.LogError` 后 return，**`onComplete` 不执行 → `LoadScene` 永远不调用**
- `UI/TransitionEffect.cs:139-143,175-179`：`exitPanel == null` 时直接 return 不加载场景
已核实所有场景均正确序列化了 transitionMaterial，正常不触发；但这是唯一场景跳转通道，配置一旦丢失（材质引用丢失/Shader 缺失）玩家点击按钮无反应、游戏"卡死"。
修复：空引用分支 fallback 到直接 `SceneManager.LoadScene(sceneName)`。

### P1-2 运行时反射硬编码程序集名（4 处）
- `Combat/Repository/RuntimeGameRepository.cs:472-473`：`Type.GetType("InventorySystem, Assembly-CSharp")` —— 资源读写走反射，失败时静默回落到 `FallbackResources` 双轨记账，读写可能不一致
- `Combat/Runtime/CardView.cs:569-574`：反射写 `CardInteraction` 私有字段
- `Combat/Runtime/CoffeeSlotController.cs:123-132`、`Combat/PreBattle/CoffeeSelectionUI.cs:66-75`：`Type.GetType("CoffeeIconCache, Assembly-CSharp")`
- `Combat/Runtime/BattleCardBridge.cs:99-105`：反射读 `Draggable.AnyDragging`
当前 Windows Mono 构建可用；一旦切 IL2CPP + 代码裁剪会**静默失效**（咖啡图标空白、卡牌交互失效）。且 `BattleCardBridge` 与 `CardView` 对同一属性一处反射一处直引，重复且脆弱。
修复：统一直接引用；为被反射类型加 `[Preserve]` 或 link.xml。

### P1-3 战斗结算弹窗空引用
`Combat/Runtime/HuntResultPresenter.cs:291`（`cardArea.childCount` 未判空）、`:300`（`extraCardsText.text` 未判空）
同文件其它字段（titleText/lootText/goldText）都有判空，唯独这两个没有。漏配场景引用时胜/败结算弹窗期间 NRE 卡死流程。
修复：补判空或降级文案。

### P1-4 资源 JSON 空/损坏时 NRE
`CoffeeShop/Inventory/ResourceDataLoader.cs:57-61`
`JsonUtility.FromJson` 对空字符串**不抛异常返回 null**，catch 抓不到，第 61 行 `_cachedDatabase.resources.Count` 直接 NRE（且此时 `IsLoaded` 已置 true，状态错乱）。
修复：`FromJson` 后判 `if (_cachedDatabase == null) { Fail(...); return; }`。`LoadDirect()`（92 行）同样处理。

### P1-5 开场对话协程无超时，可能永久卡死
`CoffeeShop/CafeFlow/StartOfDayController.cs:89-91`
`yield return new WaitUntil(() => left)` 依赖 NPC 离店事件链，任一环异常（对话缺失、状态机 bug）则游戏永远停在开场。
修复：加超时兜底（如 15 秒强制完成）。

### P1-6 敌人 AI：每回合只驱动第一个存活敌人
`Combat/Runtime/CardEnemyAI.cs:57-64,103-109`
`EnemyTurnStarted` 只对 `FindFirstLivingEnemy()` 启动一个协程，协程结束即 `CompleteEnemyTurn()`。已核实 **Card 场景仅挂 1 个 CardEnemyAI 组件** → 若玩法存在多敌人同场（精英+Boss），只有第一个敌人行动，其余整场发呆。
修复：`RunEnemyTurn` 改为对全部存活敌人串行 `ExecuteTurn` 后再 `CompleteEnemyTurn`。
> 若当前玩法确认单敌人战斗，本项可降级为 P2 并备注。

### P1-7 QTE 系统未接入（半成品功能上线）
`CoffeeShop/Reward/Rewarder.cs:23` + 全项目检索确认
- `order.QTEScore` **全项目无任何赋值点**（仅定义、自身拷贝、读取 3 处），`IsAllPerfect()` 恒为 false → **Perfect 奖励 250 金币永不触发**
- 5 个 QTE 子类（DropStop/HoldRelease/RapidTap/RhythmTap/RotationStop）的 `Show()` 无任何业务调用者，整体是死代码；`CoffeeData.CraftStep.qteType` 已定义但无人消费
修复：产品决策二选一——(a) 在 `CraftController.Deliver` 接入 QTE 流程并填充 `QTEScore`；(b) 本期不上 QTE，删除 Rewarder 的 bonus 分支与 UI 文案。

### P1-8 咖啡杯合并后仍可继续塞材料（状态不一致）
`CoffeeShop/CoffeeCraft/CupContainer.cs:36-48,52-88`
`MergedCoffeeId` 置位后 `AcceptIcon` 仍接受新材料，但交付判定按旧 `MergedCoffeeId` 匹配 → "多塞材料也能按已合并配方交付"，可被利用或少扣材料。
修复：`AcceptIcon` 开头 `if (MergedCoffeeId != null) return false;`。

### P1-9 半成品咖啡图标映射错误
`CoffeeShop/CoffeeCraft/CoffeeIconCache.cs:65,67`
`_halfSprites["Sunset"]` 和 `["TheFifthFlavor"]` 都错误指向 `eyeMilkHalf`；`sunsetHalf`/`theFifthFlavorHalf` 字段从未使用 → 这两款咖啡的半成品态显示错误图标。
修复：改为各自字段。

### P1-10 事件总线不去重，重复订阅=逻辑双执行
`CoffeeShop/Core/GameEvent.cs:24-33`
`On()` 不做重复检查，同一 handler 重复订阅时 `Emit` 执行两次。当前组件 OnEnable/OnDisable 配对良好未触发，但组件重复放置/Enable 顺序异常时，`Rewarder.OnOrderCompleted` 这类订阅 → **加钱双倍**。
修复：`On` 时 `if (handlers.Contains(handler)) return;`。

### P1-11 StreamingAssets 校验无容错，打包漏资源即启动崩溃
- `Combat/Progression/LoopProgressionRepository.cs:217-230`：`EnsureLoaded()` 无 fallback，JSON 缺失直接抛 `FileNotFoundException`；`ValidateStreamingAssetReferences()`（173-192）强校验 resources.json 与 CoffeeData 目录，缺失抛 `DirectoryNotFoundException` → **启动即崩**
- `Combat/Event/EventJsonRepository.cs:30-31,145-156`：`Load()` 的 catch 里调 `CreateFallback()`，而 fallback 访问 `LoopProgressionRepository.FinalDay` 会在 catch 块内再次抛异常 → 连锁崩溃
修复：LoopProgression 加默认数据 fallback；EventJsonRepository 的 fallback 缓存默认 FinalDay 常量；**打包检查清单中加入"验证三个 JSON 目录完整"**。

### P1-12 卡组标签乱码（玩家可见）
`Combat/PreBattle/CardSelectionUI.cs:813`
`deckLabel.text = $"已选卡�?({...})"` —— 字符串含 U+FFFD 替换字符（源文件编码损坏），玩家会看到坏字。
修复：改为 `"已选卡组"` 或 `"已选卡牌"`。
